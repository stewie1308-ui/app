# Inkling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An offline Android micro-learning app ("Inkling"). Each day it serves about 5 guess-first fact cards with spaced repetition, a gentle streak, a browse feed, and downloadable card packs. GitHub Actions builds the app and attaches the APK to a Release.

**Architecture:** A static web app in `www/`: plain HTML, CSS and ES modules, no framework. Logic lives in small pure modules tested with `node --test`; `www/js/ui/*` renders screens. Capacitor 8 wraps `www/` as a native Android app. The `android/` project is generated locally with `npx cap add android` and committed. CI only runs Gradle and publishes the APK.

**Tech Stack:** Capacitor 8.6 (`@capacitor/core`, `@capacitor/android`, `@capacitor/app`), Node 22 `node:test`, fonts from `@fontsource/fraunces` and `@fontsource/source-sans-3` copied into `www/fonts`, Python PIL for the app icon, GitHub Actions (`ubuntu-latest`, JDK 21).

**Spec:** `docs/superpowers/specs/2026-11-22-inkling-design.md`

**Execution:** Native (executing-plans). The user is asleep, and Claude only spawns subagents when the user asks for them.

## Global Constraints
- App name "Inkling"; app id `com.stewie.inkling`.
- Fully offline except the "Get more cards" button. Packs are fetched from `https://raw.githubusercontent.com/stewie1308-ui/app/main/packs/index.json`.
- No accounts, ads, tracking or paywall.
- Card body ≤ 60 words. Every card has a source link. Facts are written in Claude's own words; the content licence is CC BY-SA 4.0.
- Starter set ≥ 400 cards, 100 per topic: `science`, `history`, `how`, `words`.
- Intervals for a correct answer: 1 → 3 → 7 → 16 → 35 days, then mastered. A wrong answer is due tomorrow.
- Session size is 3, 5 (default) or 10. Due reviews come first, but 2 slots are kept for new cards when any are left (Claude's call).
- Streak: one answered card counts for the day. Two automatic freezes per ISO week.
- Paper & Ink look: cream `#F6F0E4` paper, ink `#2B2620`. Topic colours: sage `#7A9471` (science), terracotta `#B8613E` (history), ochre `#C4932F` (how), slate `#5C7185` (words). Headlines in Fraunces, body text in Source Sans 3.
- Release APK named `Inkling.apk`, published to a GitHub Release tagged `v1.0.<run_number>` and marked latest. `versionCode` = run number.

## Review Focus
1. **The day boundary uses local time:** a card answered at 23:30 London time counts for that day, and at 00:10 for the next. Tested by `dayKey` tests with a fixed TZ (Task 1).
2. **Corrupt or missing saved data:** the app starts fresh and does not crash (Task 1, `storage` tests).
3. **No new cards left and nothing due:** the session is empty, and the home screen shows "All caught up" with Browse and Get-more options (Task 2).
4. **A pack download that is offline, malformed or full of duplicates:** the app shows an error message, existing data is kept, and duplicate ids are skipped (Task 4).
5. **A session left open overnight:** yesterday's unfinished session is dropped on the next day, and the answers already given are kept (Task 2).

### Task 1: Core logic: dates, storage, scheduling, streak
**Files:** create `www/js/dates.js`, `www/js/storage.js`, `www/js/srs.js`, `www/js/streak.js`, `test/core.test.mjs`, `package.json`

**Interfaces (produces):**
- `dayKey(date: Date) -> "YYYY-MM-DD"` (local); `addDays(key, n) -> key`; `daysBetween(a, b) -> int`; `isoWeek(key) -> "YYYY-Www"`
- `loadState() -> State`; `saveState(state)`; `defaultState()`. State is `{version:1, cards:{[id]:{box, due, seen, right, wrong, mastered}}, streak:{count,best,lastDay,freezesLeft,freezeWeek}, settings:{sessionSize:5}, session:null|{day, queue:[{id,kind}], index, results:[]}, packs:{[id]:{title,version,cards:[...]}}}`. Takes an injectable `storageImpl` for tests.
- `INTERVALS = [1,3,7,16,35]`; `grade(cardState|undefined, correct: bool, today) -> cardState`. A correct answer moves the box up by one and sets `due = today + INTERVALS[oldBox]`; a correct answer in box 4 sets `mastered=true`. A wrong answer sets box 0 and `due = today + 1`.
- `recordActivity(streak, today) -> streak`; `streakAlive(streak, today) -> bool`

- [ ] Tests: `grade` on a new card that's correct gives `{box:1, due:+1}`; box 4 correct gives `mastered`; wrong gives `box 0, due +1`. Streak: same day = no change; a 1-day gap uses a freeze; a 3-day gap with 2 freezes resets to 1; a new ISO week refills to 2. `dayKey` with `TZ=Europe/London` for 2026-06-01T23:30+01:00 gives `2026-06-01`. `loadState` with the stored string `"{bad"` returns `defaultState()`.
- [ ] Run `npm test`: FAIL, then implement, then PASS. Commit.

### Task 2: Sessions
**Files:** `www/js/session.js`, `test/session.test.mjs`
**Interfaces:**
- `buildSession(allCards, state, today, rng) -> [{id, kind:"new"|"review"}]`
- `currentSession(state, today) -> session|null`. A stale session (`day` is not today) is dropped.
- `answer(state, today, {id, kind, correct, sure}) -> state`. This grades the card, records the streak, and pushes the result. A confident miss (`sure && !correct`) also appends `{id, kind:"recheck"}` to the queue once.
- New cards rotate round-robin through the topics in a seeded shuffle.
- [ ] Tests: 7 due + size 5 + new cards available gives 3 reviews + 2 new. Nothing due and none new gives `[]`. A stale session yields null. A confident miss appends a recheck, and only once. Commit.

### Task 3: Content (≥400 cards) and validator
**Files:** `content/science.json`, `content/history.json`, `content/how.json`, `content/words.json`, `scripts/build-content.mjs` (merges into `www/content/starter.json`), `scripts/validate.mjs`, `test/content.test.mjs`
**Card schema:** `{id, topic, title, body, q:{prompt, options[2-4], answer}, rq:{prompt, options, answer}, why, source:{name, url}, visual?}`. `visual` is `{type:"timeline", points:[{label, year}]}` or `{type:"compare", items:[{label, value, unit}]}`.
- Source urls use the form `https://en.wikipedia.org/w/index.php?search=<Title>`, which always resolves.
- [ ] The validator fails on: duplicate ids, `answer` out of range, body > 60 words, a missing source, or an unknown topic. A test runs the validator on the built starter file and asserts each topic has ≥ 100 cards.
- [ ] Write the cards in batches. Use only well-established facts, avoid popular myths, and look up anything uncertain. Commit per topic.

### Task 4: Packs
**Files:** `www/js/packs.js`, `test/packs.test.mjs`, `packs/index.json`, `packs/weird-animals.json`
**Interfaces:** `mergePack(state, pack, starterIds) -> {state, added, skipped}`; `fetchIndex(fetchImpl)`; `downloadPack(fetchImpl, entry)`. Each throws `PackError` with a friendly message.
- [ ] Tests: duplicate ids are skipped; a malformed pack throws `PackError` and the state stays unchanged; fetch rejecting gives the "You're offline" message. The first pack is about 25 "Weird animals" cards (Claude's call). Commit.

### Task 5: UI (Paper & Ink)
**Files:** `www/index.html`, `www/css/app.css`, `www/js/app.js` (router and back button), `www/js/ui/home.js`, `www/js/ui/card.js`, `www/js/ui/done.js`, `www/js/ui/browse.js`, `www/js/ui/stats.js`, `www/js/ui/settings.js`, `www/js/ui/visuals.js` (SVG timeline and compare), `www/js/ui/icons.js` (inline ink SVGs: planet, hourglass, gear, quill, leaf), `www/fonts/*`
- Home: greeting by time of day, streak, a Begin/Continue button showing progress, "All caught up" when the session is empty, topic tiles, and Browse / Stats / Settings.
- Card: topic label, "2 of 5", question, options, an "I'm sure / Just guessing" toggle (default guessing). Reveal: right or wrong ("You were sure!" for a confident miss), then title, body, visual, why, source link (opens the system browser), Next. A review shows `rq` and then a short reveal.
- Browse: vertical scroll-snap feed with a topic filter; no grading.
- Settings: session size, Get more cards, reset progress (in-app confirm sheet, no `alert`), and credits/licence.
- The Android back button goes to home or closes overlays, and exits only from home.
- [ ] Verify with headless Chrome screenshots at 412×915 of home, question, reveal, browse, settings and done. Look at each, fix, commit.

### Task 6: Android wrapper and CI release
**Files:** `capacitor.config.json`, `android/` (generated), `scripts/make-icons.py`, `.github/workflows/build.yml`, `README.md`
- `npx cap add android`, then `npx cap sync`. Generate launcher icons for every mipmap density, including the adaptive foreground and background. Set the status bar and background colour to cream.
- Signing: `android/app/build.gradle` reads `INKLING_KEYSTORE` (base64), `INKLING_STORE_PASS` and `INKLING_KEY_ALIAS` from the environment. Keys go in repo secrets via `gh secret set`. If the API refuses, commit `android/inkling.keystore` and tell the user.
- Workflow: on push to main, run `npm ci && npm test && node scripts/build-content.mjs && npx cap sync android`, then `./gradlew assembleRelease`. Rename the output to `Inkling.apk`, then `gh release create v1.0.$RUN --latest`.
- [ ] The workflow run goes green, and `https://github.com/stewie1308-ui/app/releases/latest/download/Inkling.apk` returns the APK. Commit and push.
